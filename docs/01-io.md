# 3.1 点云在内存里到底怎么储存的

## 头文件找不到

第一次打开 `01_io.cpp`，`#include <pcl/point_cloud.h>` 下面一般会标红，F12 也跳不进去。如果编译正常而编辑器报找不到头文件，通常是**语言服务器（LSP）没有拿到编译参数**。

在工作空间根目录执行：

```shell
catkin_make -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
ln -sf build/compile_commands.json compile_commands.json
```

然后重开语言服务器（Reload Window）。

具体过程如下：

```
catkin_make -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
   │
   ├─ catkin_make 只是把参数转给 cmake
   ├─ cmake 根据 find_package(PCL)、include_directories() 算出每个 .cpp 真正的编译命令
   │    （里面有 -I/usr/include/pcl-1.10）
   └─ 把这份命令清单写成 build/compile_commands.json
                                ↓
                    语言服务器读它，才能找到头文件
```

语言服务器会从源文件所在目录开始，一级一级找它的父级目录。`compile_commands.json` 生成在 `build/` 里，而源文件在 `src/`，`build/` 不是 `src/` 的父级，所以找不到。在仓库根目录做这个软链，根目录是各级源文件的父级，找的时候就会命中。

## 点云的类型

PCL 在 C++ 里用 [`pcl::PointCloud`](https://pointclouds.org/documentation/classpcl_1_1_point_cloud.html) 这个类表示点云，头文件是 `<pcl/point_cloud.h>`。它是模板类：

```cpp
// pcl 命名空间内的类声明，省略实现
template <typename PointT>
class PointCloud;
```

尖括号是 C++ 的**模板**：`PointCloud` 的点类型由模板参数指定。

```cpp
pcl::PointCloud<pcl::PointXYZI> cloud;   // PointXYZI 的点云
pcl::PointCloud<pcl::PointXY>   cloud2d; // 二维点组成的点云
```

这两行是两个完全不同的类型，编译器照着模板各生成一份。尖括号里只能填类型，而且不能空着。

`PointXYZI` = `Point + X + Y + Z + I`。**I 是 intensity（反射强度）**，激光打出去弹回来有多强。它跟材质、颜色、距离都有关，不是亮度，也不是固定的 0~255，不同雷达标定不一样。

头文件：

```cpp
#include <pcl/point_cloud.h>   // pcl::PointCloud
#include <pcl/point_types.h>   // 各种点类型
```

| 点类型                 | 字段                   | 用途                 |
| ---------------------- | ---------------------- | -------------------- |
| `pcl::PointXYZ`        | x y z                  | 只要坐标             |
| `pcl::PointXYZI`       | x y z intensity        | 激光点，最常用       |
| `pcl::PointXYZRGB`     | x y z rgb              | 彩色点云             |
| `pcl::Normal`          | normal_x/y/z curvature | 法线                 |
| `pcl::PointXYZINormal` | xyz + intensity + 法线 | 一次存全             |
| `pcl::PointXY`         | x y                    | 压成 2D 之后         |

表中的点类型都是普通结构体，不需要模板参数。

## 内存占用

`sizeof` 实测（PCL 1.10 / 64 位）：

| 类型                   | sizeof | alignof |
| ---------------------- | ------ | ------- |
| `pcl::PointXYZ`        | 16     | 16      |
| `pcl::PointXYZI`       | **32** | 16      |
| `pcl::PointXYZRGB`     | 32     | 16      |
| `pcl::Normal`          | 32     | 16      |
| `pcl::PointXYZINormal` | 48     | 16      |
| `pcl::PointXY`         | 8      | 4       |

4 个 float 为什么是 32 字节：点类型用 `EIGEN_ALIGN16` 做 16 字节对齐（SIMD 一次读 4 个 float），结构体大小必须是 16 的倍数，20 就补到 32。

| 点数     | `PointXYZ` 16B | `PointXYZI` 32B |
| -------- | -------------- | --------------- |
| 1 万     | 160 KB         | 320 KB          |
| 10 万    | 1.6 MB         | 3.2 MB          |
| 100 万   | 16 MB          | 32 MB           |
| 500 万   | 80 MB          | 160 MB          |
| 5000 万  | 800 MB         | 1.6 GB          |

一帧 Mid360 约 2 万点，640 KB。我们实验室那张 547 万点的图（`ros_libraries_ws/src/FAST_LIO/PCD/scans.pcd`）换成 `PointXYZINormal` 是 262 MB。

**文件大小 ≠ 内存大小**：`demo_room.pcd` 是 1.8 MB（16 B/点），读成 `PointXYZI` 后是 3.5 MB。

### 对齐和内存分配

对齐不只影响 `sizeof`，还影响**怎么分配内存**。

`pcl::PointCloud` 内部的容器不是普通的 `std::vector<点>`，而是 `std::vector<点, Eigen::aligned_allocator<点>>`。第二个模板参数是分配器，专门负责按 16 字节对齐分配——因为点类型要求地址是 16 的倍数。这样能满足点类型对内存对齐的要求。C++17 已支持按类型的对齐要求分配内存，本工程也使用 C++17；不能一概认为普通 `std::vector` 都会导致段错误。

如果自定义类直接包含 Eigen 的定长向量等需要对齐的成员，在较旧编译标准或特定平台上还要处理对象本身的分配。PCL 提供了相应宏：

```cpp
class Detector {
  PCL_MAKE_ALIGNED_OPERATOR_NEW
  Eigen::Vector4f position_;
};
```

这个宏用于兼容需要显式处理对齐的环境。只包含 `PointCloud` 容器本身，不等于直接包含一个需要 16 字节对齐的点对象。

## Ptr

```cpp
pcl::PointCloud<pcl::PointXYZI>::Ptr cloud;
pcl::PointIndices::Ptr               inliers;
pcl::ModelCoefficients::Ptr          coeffs;
```

这两个类型也是普通结构体，不需要模板参数：

```cpp
// pcl 命名空间内的声明，省略实现
struct PointIndices;
struct ModelCoefficients;
```

后两个是另外两种类型：`PointIndices` 表示一组点的下标，`ModelCoefficients` 表示一个几何模型的参数（平面的 a、b、c、d）。[3.8 扩展](08-extend.md) 里的找平面会用到。

`::Ptr` 是类自己 typedef 出来的智能指针（PCL 1.10 里是 `boost::shared_ptr`），`::ConstPtr` 是只读版。智能指针可以像普通指针一样用 `->` 访问成员。

智能指针是什么、跟裸指针（`T*`）有什么区别，请自行了解，这里不展开。创建点云用 `pcl::make_shared<T>()`，不要写裸的 `new`。

```cpp
pcl::PointCloud<pcl::PointXYZI>::Ptr cloud =
    pcl::make_shared<pcl::PointCloud<pcl::PointXYZI>>();
```

`pcl::make_shared` 不用单独 include，`<pcl/point_cloud.h>` 里已经包含了 `<pcl/make_shared.h>`；`PointCloud` 本身也在这个头文件里。只 include `<pcl/point_types.h>` 是不够的。

PCL 的大多数函数接口都接收 `Ptr`，是因为一张点云几十上百 MB，按值传一次就拷贝一次。

`PointCloud` 有 `size()`、`operator[]`、`push_back()`、`resize()`，和 vector 一样用。

两张点云可以直接相加、赋值：

```cpp
Cloud a, b;
a += b;    // 把 b 的点接到 a 末尾，width、height、is_dense 跟着更新
a = b;     // 拷贝内容，之后改 b 不影响 a
```

执行 `p1 = p2` 后，两个指针指向同一张点云，通过其中一个修改点云，另一个也能看到。要拷贝点云内容，写 `*p1 = *p2`。

## 三个字段

`PointCloud` 用起来和 `std::vector<点>` 差不多，区别是它多了 `width`、`height`、`is_dense` 这几个字段，点本身仍然放在 `points` 里。

- `width` / `height`：无序点云 `height=1`、`width=点数`；有序点云 `width × height = 点数`。
- `is_dense`：为 `true` 表示点的数值都是有限值；可能包含 NaN / Inf 时应设为 `false`。
- `points`：真正的数据，`cloud->points[i]` 是第 i 个点。

## 用 pcl_viewer 查看

```shell
pcl_viewer data/demo_room.pcd
```

PCL 自带的查看器，不用开 ROS。左键拖拽旋转，滚轮缩放。路径是相对当前目录的，要在仓库根目录执行。

`pcl_viewer` 不在 ROS 的 PCL 包里（`pcl_ros`、`libpcl-dev` 都不包含它），要单独安装：

```shell
sudo apt update
sudo apt install pcl-tools
```

装完 `which pcl_viewer` 能看到 `/usr/bin/pcl_viewer` 就对了。`apt update` 这一步不能省：镜像里的软件包索引可能是空的，不更新会报 `Unable to locate package pcl-tools`。

### 要用的东西

`pcl::PointCloud` 的成员：

```cpp
std::size_t size () const;      // 点数
std::uint32_t width;
std::uint32_t height;
bool is_dense;
VectorType points;              // 存点的容器，points[0] 是第 0 个点
```

这几个成员的说明见 [`pcl::PointCloud` API](https://pointclouds.org/documentation/classpcl_1_1_point_cloud.html)。

包围盒：

```cpp
template <typename PointT>
void getMinMax3D (const pcl::PointCloud<PointT> &cloud, PointT &min_pt, PointT &max_pt);
```

`getMinMax3D` 的签名见 [pcl::common 模块](https://pointclouds.org/documentation/group__common.html#ga3166f09aafd659f69dc75e63f5e10f81) 里同名的那几条。

`pcl::io`：

```cpp
template <typename PointT>
int loadPCDFile (const std::string &file_name, pcl::PointCloud<PointT> &cloud);

template <typename PointT>
int savePCDFileBinary (const std::string &file_name, const pcl::PointCloud<PointT> &cloud);
```

`loadPCDFile` 见 [查看官网 API](https://pointclouds.org/documentation/group__io.html#ga596cb153154843a6f735341ddcc4af08)，`savePCDFileBinary` 见 [查看官网 API](https://pointclouds.org/documentation/group__io.html#gaf65d12d62b6a76389771a41c8d62ea0b)。
